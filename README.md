# MdYomuKiku

Markdownで書いた小説から、読む・聴くことのできる静的サイトを生成するCLIです。普段はVS Codeなどで執筆し、コマンドで公開用HTMLを作ります。トップページと作品ごとのHTMLを生成します。

## 使い方

Node.js 22以上が必要です。

```bash
npm ci
npm run demo
```

プレビューサーバーは次のコマンドで起動できます。起動時に `novels/` の原稿を再生成し、`docs/` をルートとして配信します。

```bash
npm run dev
```

`http://localhost:5173/` を開いてください。ポートは `PORT` 環境変数で変更できます。原稿変更後は別のターミナルで `npm run build:site` を実行し、ブラウザーを再読み込みしてください。

`http://localhost:5173/` で、50作品・100話（本文合計約2万字）のオリジナル短編サンプルを読めます。作者名・作品・紹介文はサンプル用の創作です。公開するときは `docs` の内容を静的ホスティングへ配置します。このツール自体にアップロード機能はありません。

普段は `novels/作品名/` に原稿を追加・編集し、次のコマンドで生成します。

```bash
npm run build:site
```

別のフォルダーから生成する場合：

```bash
npm run build -- ./novels ./docs
```

入力と出力は別のフォルダーにしてください。出力先には生成ファイルの管理用JSONも作られます。次回生成時に、削除・非公開にした作品の以前の生成HTMLを消すために使います。公開サーバーへの反映時も削除を同期してください。

## 原稿の構成

```text
novels/
  星を運ぶ郵便屋/
    novel.json
    01-夜の配達.md
    02-宛先のない星.md
    cover.png
```

1フォルダーが1作品です。各作品内のMarkdownをサブフォルダーも含めてファイルパスの自然順（2→10）で並べ、1ファイルを1話にします。章分けには `01-第一章/01.md` などの名前を使えます。公開しないメモは作品フォルダーの外に置いてください。ドットから始まるファイル・フォルダーは除外します。入力直下にMarkdownを置いた場合は、その直下のファイルを1作品として扱います。

各話の最初の `# 見出し` が話タイトルです。なければファイル名を使います。見出し・強調・リスト・引用・表・コード・リンク・画像などのMarkdownに対応します。生のHTMLは実行せず文字として表示します。

`novel.json` は省略可能です。

```json
{
  "title": "星を運ぶ郵便屋",
  "author": "水瀬 しおり",
  "genre": "ファンタジー",
  "description": "宛先のない手紙を、夜空の向こうへ。",
  "tags": ["星空", "旅"],
  "status": "完結済",
  "priority": 100,
  "updated": "2026-10-22",
  "cover": "cover.png",
  "draft": false
}
```

- `priority`：大きいほどおすすめ順で上に表示。正の値で「おすすめ」を表示。
- `updated`：更新日。省略時はMarkdownの最終更新日。`build:site` とActionsは `--git-dates` を指定し、コミット済み原稿の最新コミット日時を使います。未コミットの新規ファイルはファイルの更新日時を使います。既存ファイルの未コミット編集を日付へ反映するには、コミットするか `updated` を指定してください。
- `draft: true`：その作品を公開対象から除外。
- `cover`：作品フォルダーからの相対パス。省略すると `cover.png` を自動検出。画像がなければ文字入りの仮表紙を表示。表紙は1024×1536px（縦横比2:3）のPNGを推奨。

本文の画像は `![説明](images/scene.png)` と書きます。各Markdownからの相対パスで指定し、作品フォルダー内のPNG・JPEG・GIF・WebP・AVIFを使用できます。画像はBase64で埋め込みます。リモート画像や作品フォルダー外のファイルは受け付けません。

## フォント

初期値は **system** です。

```bash
npm run build -- ./novels ./docs --font system
npm run build -- ./novels ./docs --font embed
npm run build -- ./novels ./docs --font external
```

| 値 | 動作 |
| --- | --- |
| `system` | 初期表示は端末の標準フォント。HTMLへフォントは埋め込まず、ふりがな用の共有ファイルを `assets/` に出力 |
| `embed` | Furifontを各HTMLへBase64で埋め込む。各ページ約8.7MB増加 |
| `external` | `assets/FurifontSans-Regular.woff2` を全HTMLで共有。HTMLとassetsを一緒に公開 |

Furifont Sans Regular v0.6.2を収録しています。`system` でも本文の「ふりがな → あり」で共有フォントを必要時に読み込みます。初期値は「なし」です。`docs/assets/` も一緒に公開してください。HTML単体で持ち出した場合、標準フォントでの閲覧は可能ですが、この切り替えには共有フォントが必要です。ふりがなはフォントの合字で描かれ、文脈や固有名詞で読みが誤る場合があります。Furifont使用時は本文でふりがなを無効にし、端末フォントに切り替えられます。利用条件と出典は [assets/fonts](assets/fonts/README.md) と生成HTML内に収録しています。

## 閲覧機能

- トップ：作品一覧、タイトル・作者・紹介文・タグ検索、ジャンル絞り込み、おすすめ順・更新順・名前順。
- 作品：紹介、表紙、目次、前後の話への移動、文字サイズ、昼夜の配色。
- ユーザー：ヘッダーでブラウザー内のユーザーを切り替え。「設定」で新しいユーザーを追加できます。ログイン認証や端末間の同期はありません。
- 既読・未読：各話で手動切り替え、作品全話の一括切り替え。開くだけでは既読にしません。目次と一覧に進捗を表示します。話のファイルパスで記録するので、話を途中へ追加しても既読がずれません。原稿ファイルを移動・改名すると、その話は別の話として扱います。
- お気に入り：一覧と作品ページで登録・解除。一覧はお気に入り・未読・読書中・既読で絞り込めます。
- 読書再開：ユーザーごとにブラウザーのlocalStorageへ最後に開いた話を保存。同じブラウザー・同じ公開先で利用できます。話の途中のスクロール位置は保存しません。`file://` での保存可否はブラウザーに依存します。
- 音声：Web Speech APIを使った本文読み上げ、一時停止・再開・停止、速度と声の選択、読んでいる段落の強調。基本の音声は「設定」で変更・試聴でき、作品で変更した声と速度はその作品用に保存。「基本の音声に戻す」で作品別の指定を解除します。各話を最後まで読んだら停止します。

既読・お気に入り・音声設定はブラウザー内のデータです。別端末へは引き継がれず、ブラウザーデータの削除で消えます。ユーザー切替は同じ端末内での使い分けで、記録を他人から保護する認証機能ではありません。

音声は端末やブラウザーの機能を使用し、音声データ自体はHTMLに含めません。利用できる声・日本語への対応・通信の必要性は端末によって異なります。フォントのふりがなと読み上げエンジンの読みは別です。

作品本文JSONとJavaScriptはBase64、CSSはインラインで保存します。`system` / `embed` なら各作品のHTML単体で本文を閲覧できます。作品一覧との相互リンクを使う場合は `index.html` と作品HTMLを同じフォルダーに置いてください。Base64は暗号化ではありません。出力された本文は閲覧者が取り出せます。

本文は作品ページにだけ含め、トップには紹介情報だけを入れます。非常に大きな作品はブラウザーのメモリーと読み込み時間を使います。ブラウザー内検索は作品情報が対象で、本文の横断検索は行いません。

現在の実装対象は小説サイトです。ブログ・商品紹介・管理画面・注文・決済は未実装です。

## 開発時の確認

```bash
npm test
npm run demo
```

自動テストはHTML生成、画像埋め込み、フォント3方式、検索・ジャンル、目次・読書再開、原稿の検証、ユーザー間の既読・お気に入りの分離、音声設定の保存・試聴、ふりがなの切り替えを対象にします。実端末のフォント描画や音声の品質はブラウザーで確認してください。

## 一覧JSONの外部化

初期値は `--catalog external` です。

```text
docs/
  index.html          ← 一覧を表示する画面
  catalog.json        ← 全作品の紹介・ジャンル・タグ・優先度・表紙
  work-….html         ← 作品ごとの本文入りHTML
  .nojekyll
```

作品を追加・更新すると、CLIが `catalog.json` と対象作品のHTMLを生成します。デザインやスクリプトが同じなら `index.html` 自体は変わりません。`catalog.json` は生成物なので、直接編集せず `novels/作品名/novel.json` を編集してください。削除した作品は一覧と旧作品HTMLからも除きます。

外部JSONはHTTP経由で読み込むので、プレビューは `npm run dev` を使用してください。一覧を含めてHTMLを直接開きたい場合は埋め込み方式も選べます。

```bash
npm run build -- ./novels ./docs --catalog embed
```

一覧JSONの外部化とフォントの `--font` は別々に選べます。作品本文はどちらの方式でも作品HTML内に保存します。外部JSONが読めない場合には、画面に起動方法と再読み込みボタンを表示します。

## GitHub ActionsとPages

初回設定、実行間隔の変更、コメント化による停止・再開は [GitHub Actionsの設定手順](guides/github-actions.md) を参照してください。

[.github/workflows/publish.yml](.github/workflows/publish.yml) が以下のタイミングで `novels/` から `docs/` を生成します。

- `main` へ原稿・画像・生成コードなどの変更をpushしたとき。
- 1日2回、UTCの0:17・12:17（日本時間の9:17・21:17）の定期実行。変更がなければコミットも再デプロイもしません。
- Actionsの「Run workflow」で手動実行したとき。

追加だけでなく、編集・作品削除・`draft: true` への変更も反映します。ローカルの原稿はpushして初めてActionsから参照できます。定期実行はGitHub側の混雑などで遅れる場合があります。

初回の設定：

1. 原稿、コード、ワークフローを `main` に反映します。
2. Settings → Actions → General → Workflow permissions で、ワークフローによるリポジトリへの書き込みを許可します。ブランチ保護がある場合は、自動コミットを許可できる設定が必要です。
3. Settings → Pages → Build and deployment → Source を **GitHub Actions** にします。以前 `/docs` のブランチ公開にしていた場合も、ここを変更します。
4. Actions → Build novels and publish Pages → Run workflow で最初の公開を実行します。

ワークフローはテスト後に生成し、差分がある場合のみ `docs/` を自動コミットします。その後、`docs/` をPagesへデプロイします。自動コミットが別のPagesビルドを起動することには依存しません。push競合時は強制上書きをせず失敗するため、次の定期実行または手動実行で最新の原稿から生成し直してください。

ローカルで `docs/` を生成して `/docs` のブランチ公開を使う従来の運用も可能ですが、その場合はActionsの公開ワークフローを無効にしてください。

表紙用プロンプトは [guides/cover-prompts.md](guides/cover-prompts.md)、機械可読版は [guides/cover-prompts.json](guides/cover-prompts.json) にあります。
